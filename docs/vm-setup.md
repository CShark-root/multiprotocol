# Тестовая виртуалка (Hyper-V, Windows 11 Pro)

Виртуалка повторяет VPS: Ubuntu 22.04, 1 vCPU, 2 ГБ RAM, 25 ГБ диска. Сеть идёт мостом в домашнюю сеть, поэтому телефон по Wi-Fi видит её как обычный сервер.

## 1. Включить Hyper-V (один раз)

PowerShell **от имени администратора**:

```powershell
Enable-WindowsOptionalFeature -Online -FeatureName Microsoft-Hyper-V -All
```

Затем перезагрузить компьютер. Если команда пишет, что виртуализация выключена в BIOS/UEFI, нужно включить там Intel VT-x или AMD-V (SVM).

## 2. Скачать Ubuntu

С <https://releases.ubuntu.com/22.04/> скачать последний `ubuntu-22.04.x-live-server-amd64.iso` (около 2 ГБ), например в «Загрузки».

## 3. Создать виртуалку

PowerShell **от имени администратора**, из папки проекта:

```powershell
.\scripts\vm\create-vm.ps1 -IsoPath "$env:USERPROFILE\Downloads\ubuntu-22.04.5-live-server-amd64.iso"
```

Скрипт:
- создаёт внешний коммутатор `panel-ext` на адаптере `Ethernet` (интернет на компьютере пропадёт на пару секунд);
- создаёт VM `panel-vm` (Gen 2, Secure Boot для Ubuntu, 1 vCPU, 2 ГБ, 25 ГБ);
- запускает её и открывает окно консоли.

## 4. Установить Ubuntu

В установщике всё по умолчанию, кроме:
- **SSH Setup** → поставить галочку **Install OpenSSH server**;
- имя пользователя и пароль — любые (пароль понадобится для `sudo`).

После установки нажать «Reboot Now». Если VM снова загрузится с установщика, в Hyper-V Manager → VM → Settings → DVD Drive выбрать «None».

Узнать IP виртуалки: войти в консоль и выполнить `ip -4 addr`. Нужен адрес вида `192.168.x.y` на интерфейсе `eth0`. Удобно закрепить этот IP за VM в настройках роутера (DHCP reservation).

## 5. Вход по ключу и чекпоинт

На компьютере (обычный PowerShell), подставив своего пользователя и IP:

```powershell
ssh-keygen -t ed25519
```

```powershell
type $env:USERPROFILE\.ssh\id_ed25519.pub | ssh user@192.168.1.50 "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

Проверить, что `ssh user@192.168.1.50` входит без пароля. Потом в PowerShell от администратора сделать снимок чистой системы, к которому можно откатиться за секунды:

```powershell
Checkpoint-VM -Name panel-vm -SnapshotName clean
```

Откат: `Restore-VMCheckpoint -VMName panel-vm -Name clean -Confirm:$false`.

## 6. Поставить панель

Из папки проекта (обычный PowerShell):

```powershell
.\scripts\vm\deploy.ps1 -Target user@192.168.1.50
```

Скрипт собирает панель, копирует её на VM и устанавливает:
- пользователь `panel`, бинарь `/usr/local/bin/panel`, сервис `panel.service`, данные в `/var/lib/panel`;
- Xray из официального релиза с проверкой контрольной суммы (только в первый раз).

В конце скрипт печатает **секретный адрес панели** и отпечаток сертификата. Повторный запуск обновляет панель, данные сохраняются. Если менялся только Go-код и сборка уже есть, можно добавить `-SkipBuild`.

Полезное на VM:

```bash
sudo journalctl -u panel -f
```

```bash
sudo -u panel panel show-url -data-dir /var/lib/panel
```

## 7. Проверить

1. Открыть адрес панели в браузере. Сертификат самоподписанный, поэтому браузер предупредит. Сверить отпечаток с тем, что напечатал скрипт, и продолжить.
2. Создать администратора, на обзоре проверить, что ядро **xray** «ждёт первого подключения».
3. «Подключения» → «Новое подключение» → XHTTP + Reality, порт 443. Через несколько секунд баннер должен стать зелёным: «Xray … работает».
4. «Пользователи» → добавить пользователя → «Подключить устройство».
5. На телефоне (в той же Wi-Fi) в **v2rayNG** или **Hiddify** отсканировать QR **отдельного способа** (ссылка `vless://`).
   Ссылка-подписка с самоподписанным сертификатом может не загрузиться в клиенте: приложения проверяют сертификат. Это решат сертификаты Let's Encrypt, а внутри домашней сети их не получить, поэтому для VM используем QR отдельных способов.
6. Подключиться и открыть пару сайтов. Через минуту-две у пользователя должен появиться трафик.
7. Добавить TCP + Vision и gRPC (на других портах) и сравнить.

Что прислать, если что-то не так: текст баннера на странице «Подключения» и вывод `sudo journalctl -u panel -n 100 --no-pager`.
