# Переезд

Здесь три случая: перейти на MultiProtocol с 3x-ui, перевезти панель на новый сервер и перевезти туда же Amnezia, не настраивая роутеры заново.

Прежде чем что-то делать, сделайте снапшот VPS у хостера, если он это умеет. Если что-то пойдёт не так, откатиться можно за минуту.

## С 3x-ui на MultiProtocol

Пока 3x-ui держит 443, наша панель ставится рядом и работает на других портах. 3x-ui выключаем в самом конце, когда всё проверено.

Сначала посмотрите, что на сервере, скрипт ничего не меняет:

```bash
curl -fsSL https://raw.githubusercontent.com/CShark-root/multiprotocol/main/scripts/vps-check.sh | sudo bash
```

Он покажет, кто занимает 443, какие порты у Amnezia, есть ли файрвол и сколько остаётся памяти.

Ставим панель:

```bash
curl -fsSL https://raw.githubusercontent.com/CShark-root/multiprotocol/main/install.sh | sudo bash
```

В конце установщик напишет адрес панели и отпечаток сертификата. Откройте адрес, браузер поругается на самоподписанный сертификат: сверьте отпечаток и продолжайте. Создайте администратора и сразу включите 2FA.

Если на сервере включён ufw, откройте порт панели (`sudo ufw allow ПОРТ/tcp`), а потом порты подключений, когда будете их создавать.

Дальше в панели:
1. Создайте VLESS + Reality + XHTTP. Порт предложится свободный, пока 443 занят 3x-ui. Проверьте его с телефона.
2. Добавьте остальное, что нужно: Hysteria2, TUIC и так далее.
3. Настройте маршрутизацию: WARP, правила для России, гео-базы.
4. Если есть домен, подключите его в «Настройки → Доступ → Домен» и выпустите сертификат.

Когда всё работает, выключите 3x-ui:

```bash
sudo systemctl disable --now x-ui
```

Пока не удаляйте его совсем. Если что-то сломается, он возвращается командой `sudo systemctl enable --now x-ui`. Перенесите основное подключение на порт 443, приложения подхватят это при обновлении подписки. Через неделю спокойной работы 3x-ui можно удалить: `x-ui uninstall`.

## Панель на новый сервер

На новом сервере сначала поставьте панель обычной командой установки. Потом перенесите туда резервную копию со старого: переедут пользователи, подключения с ключами, маршрутизация и настройки бота. У клиентов меняется только адрес сервера, а если ссылки идут через домен, не меняется ничего.

Перед переездом стоит проверить новый сервер: скорость, пинг и чистоту IP. Как это сделать, написано в конце.

На старом сервере сделайте копию:

```bash
sudo -u panel panel backup -data-dir /var/lib/panel -out /tmp/mp-backup.tar.gz && sudo chmod 644 /tmp/mp-backup.tar.gz
```

Отправьте её на новый сервер прямо со старого:

```bash
scp /tmp/mp-backup.tar.gz root@IP_НОВОГО:/tmp/
```

Можно взять и `.mpbk`, который каждый день присылает бот, только при восстановлении понадобится его пароль.

На новом сервере восстановите копию:

```bash
sudo systemctl stop panel
```

```bash
sudo chown panel:panel /tmp/mp-backup.tar.gz && sudo -u panel panel restore -data-dir /var/lib/panel /tmp/mp-backup.tar.gz
```

```bash
sudo systemctl start panel && sudo -u panel panel show-url -data-dir /var/lib/panel
```

Панель напишет, что прежние файлы сохранены с окончанием `.before-restore`. Это база, которая была на новом сервере до восстановления, на случай отката. Адрес панели, логин и пароль теперь как на старом сервере.

Если в ссылках клиентов был IP старого сервера, а не домен, поменяйте его:

```bash
sudo -u panel panel set-host -data-dir /var/lib/panel IP_НОВОГО
```

Сразу после восстановления на новом сервере:
- **Проверьте IPv6.** Если `curl -6 -s -m 5 -o /dev/null -w "%{http_code}" https://www.google.com` пишет `000`, IPv6 у сервера не работает. Тогда в «Маршрутизация → DNS» поставьте стратегию «только IPv4».
- **Не трогайте пока WARP.** Устройство WARP общее со старым сервером. «Перевыпустить» на новом удалит его и у старого, а тот ещё работает. Перевыпустите, когда старый будет выключен.
- **Выключите бота на старом сервере** («Управление через бота»), иначе две панели будут отвечать одному боту.

Когда подключения на новом сервере проверены, переключите домен. В «Настройки → Доступ → Домен» выберите «IP этого сервера (автоматически)», сохраните и перевыпустите сертификат. Через минуту приложения пойдут на новый сервер сами.

Старую панель после этого можно остановить. Контейнеры Amnezia от этого не пострадают:

```bash
sudo systemctl disable --now panel
```

Теперь на новом сервере нажмите «WARP → Перевыпустить», а когда всё будет в порядке, удалите старую базу и копию:

```bash
sudo rm -f /var/lib/panel/*.before-restore /tmp/mp-backup.tar.gz
```

## Amnezia на новый сервер

Если перенести файлы контейнера вместе с ключами, клиентов не придётся создавать заново. На роутерах и в приложениях поменяется только адрес сервера. Keenetic принимает в адресе пира только IP, домен туда не впишешь, поэтому одну строку на роутере поменять всё равно придётся.

На старом сервере сохраните файлы AmneziaWG:

```bash
sudo mkdir -p /root/awg-backup && sudo docker cp amnezia-awg2:/opt/amnezia/awg/. /root/awg-backup/ && ls /root/awg-backup
```

Там должны быть `awg0.conf`, `clientsTable` и файлы ключей. В них лежат приватные ключи сервера, никому их не пересылайте. Отправьте папку на новый сервер:

```bash
scp -r /root/awg-backup root@IP_НОВОГО:/root/
```

На новом сервере поставьте AmneziaWG через приложение Amnezia («Добавить сервер», свой сервер по SSH) и в настройках протокола задайте **тот же порт**, что был на старом. Проверьте, что контейнер называется так же и слушает тот же порт:

```bash
sudo docker ps --format '{{.Names}}  {{.Ports}}'
```

Если панель на новом сервере пишет, что Amnezia нет, перезапустите её помощник: `sudo systemctl restart panel-amnezia`. Обычно так бывает, когда Docker поставили уже после панели.

Сохраните на всякий случай то, что создало приложение, и подложите старые файлы:

```bash
sudo mkdir -p /root/awg-new-original && sudo docker cp amnezia-awg2:/opt/amnezia/awg/. /root/awg-new-original/
```

```bash
sudo docker cp /root/awg-backup/. amnezia-awg2:/opt/amnezia/awg/ && sudo docker restart amnezia-awg2
```

Проверьте, что клиенты на месте:

```bash
sudo docker exec amnezia-awg2 awg show awg0 | grep -E "listening port|peer"
```

На роутере в подключении AmneziaWG поменяйте у пира адрес сервера на новый IP, порт оставьте прежним. Ключи, адрес роутера в туннеле, разрешённые подсети и параметры обфускации трогать не нужно, они переехали вместе с файлами.

Старый сервер держите, пока все роутеры не заработают через новый. Потом удалите копии ключей на обоих серверах:

```bash
sudo rm -rf /root/awg-backup /root/awg-new-original
```

## Как проверить сервер до переезда

Скорость сервера в интернет:

```bash
curl -s -o /dev/null -w "%{speed_download} байт/с\n" "https://speed.cloudflare.com/__down?bytes=200000000"
```

Скорость от сервера до вас. Это самое показательное, потому что здесь проходит реальный маршрут. На сервере:

```bash
cd /tmp && dd if=/dev/urandom of=test.bin bs=1M count=200 && python3 -m http.server 8080
```

На своём компьютере (PowerShell):

```bash
curl.exe -o NUL -w "%{speed_download} байт/с\n" http://IP_СЕРВЕРА:8080/test.bin
```

Потом Ctrl+C на сервере и `rm /tmp/test.bin`. Байты в секунду переводятся в мегабиты делением на 125 000.

Пинг: `ping -n 20 IP_СЕРВЕРА`. IP проверяется на `isitblockedinrussia.com`, `scamalytics.com` и `ipinfo.io`.

Самая важная проверка — подключение с телефона на мобильном интернете. Мобильные операторы режут сильнее домашних. Поставьте панель, нажмите «Тестовый набор» и попробуйте VLESS и Hysteria2 из подписки тестового пользователя.
